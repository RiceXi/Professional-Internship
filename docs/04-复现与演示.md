# 复现与演示

以下命令均在仓库根目录执行。CPU 仿真和 CUDA 推理分别配置环境。

## 1. CPU 仿真与测试

需要 Python 3.10+：

```bash
bash scripts/setup_cpu.sh
python3 simulate.py --seed 42 --frames 32 --block-size 4
python3 scripts/demo_memory.py
```

`setup_cpu.sh` 创建 `.venv-cpu`，安装锁定版本的覆盖率工具并运行测试。仿真和演示脚本只依赖标准库，结果默认写入 `experiments/local/`。

修改代码后，可以单独运行测试：

```bash
.venv-cpu/bin/python test/run_cpu.py --coverage
```

测试失败或覆盖率低于 70% 时，命令返回非零退出码。在安装了 PyTorch 的环境运行同一命令，还会执行三项 CPU 张量测试；未安装时这三项会跳过。

## 2. 复现实验数据

```bash
python3 bench/bench_memory.py
```

实验脚本会更新 `experiments/task1/` 下的 `raw.json` 和 `summary.csv`。也可以通过 `--output experiments/local/repro` 将新结果写入其他目录，与归档数据比较。报告和图表保留在仓库中，重跑实验后需根据新结果更新。

原始数据记录了随机种子、运行环境、提交号和源码 SHA-256。相同代码和参数下，负载及资源指标可以重复得到；运行时间等元数据会随执行环境变化。

## 3. GPU 验证

GPU 路径面向 Linux + NVIDIA CUDA，尚待在 RTX 4060 Laptop 上实测。显存容量由脚本读取，WSL 环境尚未验证。

先按照 [README](../README.md#gpu-推理与验证) 中的链接安装 PyTorch、FlashAttention 和 FlashInfer，再安装项目依赖并下载模型：

```bash
nvidia-smi
python -m pip install -r requirements.txt
python -m pip check
hf download Qwen/Qwen3-0.6B --local-dir ~/huggingface/Qwen3-0.6B
python -m pip freeze > experiments-gpu-environment.txt
```

建议按以下顺序运行，先检查页内容复制，再检查模型输出，最后做压力测试：

```bash
bash scripts/validate_gpu.sh --storage-only
bash scripts/validate_gpu.sh --model ~/huggingface/Qwen3-0.6B
python scripts/gpu_matrix.py --model ~/huggingface/Qwen3-0.6B
```

| 退出码 | 含义 |
|---|---|
| 0 | 当前验证范围通过；`--storage-only` 仅检查 CUDA 页内容 |
| 1 | 执行失败或结果不符合预期，原因保存在报告的 `reason` 字段 |
| 2 | 缺少依赖、CUDA 设备或本地模型 |

模型验证包含四种配置：充足容量参考、固定容量无换页、固定容量换页，以及固定容量共享/COW。各配置使用相同的种子、eager 执行、贪心采样和单请求轮询。充足容量配置用于核对输出，容量和性能对照使用物理块数相同的配置。

输入由固定的有效词表 ID 构成，用来稳定复现内存压力。报告保存输出 token、请求状态、逐步页指标、显存 allocated/reserved 峰值，以及搬运时间和字节数。

压力测试分别改变请求数和上下文长度，每组在独立进程运行。单次 Attention 工作集超出物理池时，结果记为 `capacity_boundary`；CUDA OOM 和其他执行错误保留为失败，具体原因可在单组报告中查看。

单次验证报告默认写入 `experiments/local/gpu_validation.json`，压力测试结果写入 `experiments/local/gpu/`。确认结果后，将报告和环境清单归档到 `experiments/task1/gpu/`，供评测报告引用。

| 0:00–0:40 | 从 README 介绍项目，说明上下文、逻辑页与物理块的关系。 |
