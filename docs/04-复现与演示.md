# 环境复现与五分钟演示

所有命令在仓库根目录执行。CPU 仿真与 CUDA 推理使用独立环境。

## 1. 无 GPU 启动

需要 Python 3.10+：

```bash
bash scripts/setup_cpu.sh
.venv-cpu/bin/python test/run_cpu.py --coverage
python3 simulate.py --seed 42 --frames 32 --block-size 4
python3 scripts/demo_memory.py
```

启动脚本创建 `.venv-cpu`，按锁定版本安装覆盖率工具并运行测试。仿真和演示本身仅使用标准库。报告默认保存到 `experiments/local/`，不会覆盖仓库归档结果。测试失败或覆盖率不足 70% 时退出非零。

可选 CPU 张量验证：在另一个兼容的 PyTorch 环境运行 `python test/run_cpu.py --coverage`。没有 torch 时三项张量测试会明确跳过；CUDA 专用适配层计入覆盖范围，未运行行不会被排除。

## 2. 重建 CPU 报告

```bash
python3 bench/bench_memory.py
.venv-cpu/bin/python -m pip install -r requirements-report.txt
.venv-cpu/bin/python scripts/plot_memory.py
python3 scripts/report_memory.py
```

此操作会重新生成 `experiments/task1/raw.json`、`summary.csv`、图表以及评测报告。保留原始数据后再比较；原始数据内的提交号、源码 SHA-256、环境和随机种子可用于追溯。不同机器的元数据不同，确定性负载和资源指标应保持一致。

## 3. RTX 4060 Laptop 实测

用户设备为 RTX 4060 Laptop，目前没有远程运行方式。建议在该设备的 Linux NVIDIA CUDA 环境中执行。具体显存容量由脚本读取，不假定所有 Laptop 配置相同；WSL 和各驱动组合尚未在本项目验证。

按根 README 的官方链接安装相互兼容的 PyTorch、FlashAttention、FlashInfer，再安装项目依赖并准备本地模型。保留实际环境清单，不将未验证的版本组合作为可复现锁定环境。

```bash
nvidia-smi
python -m pip install -r requirements.txt
python -m pip check
hf download Qwen/Qwen3-0.6B --local-dir ~/huggingface/Qwen3-0.6B
python -m pip freeze > experiments-gpu-environment.txt
bash scripts/validate_gpu.sh --storage-only
bash scripts/validate_gpu.sh --model ~/huggingface/Qwen3-0.6B
python scripts/gpu_matrix.py --model ~/huggingface/Qwen3-0.6B
```

- 退出码 0：报告指定范围验证通过；`storage_only` 只说明 CUDA 页内容检查通过。
- 退出码 1：执行或正确性断言失败，保留 reason。
- 退出码 2：缺依赖、无 CUDA 或无本地模型；不能认定验证通过。

默认先做真实 CUDA 页往返和 COW 检查，再运行充足容量参考、固定容量无换页、固定容量换页、固定容量共享/COW 四种配置。固定 eager、贪心、种子和单请求轮询。参考配置只检查输出一致性，不用其不同的容量宣称性能改善。

每个报告记录设备、显存总量、软件版本、输出 token、请求状态、逐步页指标、峰值 allocated/reserved 和搬运耗时/字节数。生成输入来自固定的有效词表 ID，只用作可复现压力测试；真实语言质量和实际对话负载需要另行补充。

压力矩阵会改变并发数和上下文长度，每组独立进程，完整保留失败结果。物理工作集超限用例是预期边界探测；矩阵会把它标为 `capacity_boundary`，不会冒充完整模型正确性通过。若出现真实 CUDA OOM，应根据异常原因单列，不能与逻辑容量拒绝混算。

结果默认在 `experiments/local/gpu/`。实测后，将报告和环境清单另存到 `experiments/task1/gpu/`，补充报告与 PPT，并提交推送；不要把模型权重加入 Git。
