# 系统与优化总览

本项目选择任务一「KV Cache 分页内存管理子系统」验收，以 Qwen3 推理为载体，研究操作系统内存管理机制如何用于 KV Cache。验收重点为分页正确性、写时复制、页面置换与空间效率；调度器和 GPU 算子负责支撑真实推理实验。

## 1. 系统分层

| 层次 | 职责 | 主要实现 |
|---|---|---|
| 控制面 | 接收请求、选择本步执行集合、推进生命周期 | `src/control/engine.py`、`scheduler.py` |
| 数据面 | 管理物理块、逻辑页表、前缀索引与批数据 | `src/data/manager.py`、`block_manager.py`、`sequence.py`、`batch.py`、`prefix/` |
| 计算面 | 加载模型、执行前向、写入 KV、采样 | `src/compute/executor.py`、`model_runner.py`、`layers/`、`models/`、`sampler.py` |

`Engine.step()` 的主要流程是调度、执行、读取采样结果、更新序列状态和回收资源。混合批次先执行 Decode，再执行 Prefill，完成后统一读取结果。

## 2. 操作系统概念映射

| OS 概念 | 推理系统中的对应 | 当前状态 |
|---|---|---|
| 进程控制块 | `Sequence` 保存 token、状态、页表与执行进度 | 已有 |
| 就绪与运行队列 | Scheduler 的 `waiting` / `running` | 已有 |
| 逻辑地址到物理地址映射 | `block_table` 与块内偏移换算物理 slot | 已有 |
| 固定大小块分配、引用计数 | `BlockManager` 管理 free / used / cached 块 | 已有 |
| 共享页 | hash / radix 复用完整前缀块 | 已有，尚无通用 fork/COW |
| 内存压力抢占 | 释放运行请求的 KV，重新入队后重算 | 已有，尚无 CPU 换入换出 |
| 锁页内存与完成事件 | Batch H2D、采样结果 D2H 与 CUDA Event | 已有 |
| 预读 | 后台读取下一份 safetensors 分片 | 已有，仅用于加载阶段 |
| 公平调度、配额与租户地址空间隔离 | 优先级、时间片、租户页表和资源限额 | 属于其他任务，本次不验收 |

## 3. GPU 执行机制

| 问题 | 当前方法 | 代码位置 |
|---|---|---|
| 分页 KV 读取前的额外搬运 | FlashAttention 直接消费页表；Decode 合批 | `src/compute/layers/attention.py` |
| 分散的 KV 写入 | Triton `store_kvcache` 合并 K/V 写入 | `src/data/kv_ops.py` |
| 逐步分配输入张量 | 常驻 GPU 缓冲与紧凑打包 | `src/data/batch.py` |
| 多次小算子启动 | FlashInfer RMSNorm、残差融合、RoPE、SiLU+Mul | `src/compute/layers/ops.py` |
| 重复读取投影输入 | 合并 QKV 与 Gate-Up GEMM | `src/compute/models/qwen3.py` |
| Decode 主机提交开销 | CUDA Graph 捕获与重放 | `src/compute/cuda_graph.py` |
| 无缓存 Prefill 前向开销 | `torch.compile` 包装首 chunk 前向 | `src/compute/model_runner.py` |
| 逐请求采样与同步 | 批量过滤、采样与结果回传 | `src/compute/sampler.py`、`model_runner.py` |

这些执行机制为真实 GPU 实验提供基础。任务一实验固定执行配置，单独对照分页、共享与换页的影响。

## 4. 如何组织实验

验收范围已确定为任务一，建议按“正确性 → 基线对照 → 压力场景 → GPU 验证”推进。具体实施尚待讨论，见[任务一验收与补齐方案](./11-任务一验收与补齐方案.md)。

- 比较连续预分配与按需分页，统计占用块、有效 token、碎片、共享和 OOM；fork/COW 与换页还需补齐。
- 使用固定调度规则回放同一组请求，避免把调度策略变化的收益混入内存管理实验。
- GPU 执行实验可以使用 eager、Decode CUDA Graph、CUDA Graph + Prefill 编译形成开关对照；它们均使用同一套分页管理，不能代替连续分配基线。

当前完整缺项概览见[项目 README](../README.md)，测量记录的适用范围见[评测方法与参考记录](./02-实测证据.md)。
