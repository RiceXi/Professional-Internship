# 本项目算子融合

> 对应 [01-推理性能瓶颈](./01-推理性能瓶颈.md) — **瓶颈 D（层内算子：Norm / RoPE / MLP）**。

RMSNorm、RoPE、SiLU 和乘法可以由多个 PyTorch 小算子组合实现。这种写法容易产生多次 kernel 启动和中间张量读写，因此项目采用专用融合内核。

例如 RoPE、SiLU+Mul 和 RMSNorm 都替换成了 FlashInfer 的实现版本，其中 RoPE/SiLU 和残差融合 RMSNorm 均注册为 custom op 以兼容 torch.compile。

## 1. RMSNorm

### 1.1 朴素实现

```python
class RMSNorm(nn.Module):
    def forward(self, x, residual=None):
        x32 = x.float()                       # Kernel 1: cast
        if residual is not None:
            x32 = x32 + residual.float()      # Kernel 2: add
        out = (x32 * torch.rsqrt(x32.pow(2).mean(-1, keepdim=True) + eps) * weight)  # pow/mean/rsqrt/mul
        return out.to(x.dtype)                # Kernel N: cast
```

一个 RMSNorm 被拆成 5~8 个独立 kernel，每个 kernel 都走一遍 HBM read → compute → HBM write，中间变量频繁读写。

### 1.2 FlashInfer 融合

```python
# 本项目 — compute/layers/layernorm.py
def forward(self, x, residual=None):
    if residual is None:
        return _rmsnorm(x, self.weight, self.eps), x
    _fused_add_rmsnorm(x, residual, self.weight, self.eps)
    return x, residual
```

`_rmsnorm` / `_fused_add_rmsnorm` 是 FlashInfer 在 `ops.py` 中注册的 `vllm::` custom op。

与独立执行残差加法和 `F.rms_norm` 相比，FlashInfer 融合核将残差相加与归一化放入一次调用。具体收益应通过 `bench/bench_rmsnorm_flashinfer.py` 和端到端实验测量。

`fused_add_rmsnorm` 会原地改写 x 和 residual，因此 custom op 必须声明 `mutates_args=("x", "residual")`，让编译器正确处理别名和副作用。



## 2. GEMM 融合

### 2.1 QKV 投影合并

朴素参考实现里 q/k/v 三个投影是三个独立 `Linear`：

```python
self.q_proj = nn.Linear(hidden, num_heads * head_dim, bias=False)
self.k_proj = nn.Linear(hidden, num_kv_heads * head_dim, bias=False)
self.v_proj = nn.Linear(hidden, num_kv_heads * head_dim, bias=False)
```

三个 GEMM 分别进行读写，而在本项目中合并为一个 GEMM：

```python
# 本项目 — compute/models/qwen3.py Qwen3Attention
self.qkv_proj = nn.Linear(
    hidden_size, (num_heads + 2 * num_kv_heads) * head_dim, bias=qkv_bias
)

def forward(self, positions, hidden_states, attn):
    qkv = self.qkv_proj(hidden_states)              # 一次 GEMM 出 q+k+v
    q, k, v = self._split_norm_rope(positions, qkv)  # 沿 dim 切分
    return self.o_proj(self.attn(q, k, v, attn))
```

输入只读一次、一次 launch；加载权重时把 HF 的 `q_proj/k_proj/v_proj` 按偏移拼进 `qkv_proj`（见 [10-模型加载](./10-模型加载.md)）。

### 2.2 MLP 的 gate/up 合并与 SiLU 融合

在朴素参考实现中，SwiGLU MLP 的计算被拆成几个独立步骤。先对输入做一次线性投影得到 gate，并经过 SiLU；再做一次线性投影得到 up；最后将两者逐元素相乘。对应到代码上大致是：

```python
gate = F.silu(x @ W_gate)   # 一次 GEMM + 一次 SiLU
up   = x @ W_up             # 一次 GEMM
out  = gate * up            # 一次逐元素乘法
```

这种写法逻辑清楚，但执行时会多出几次 kernel 启动，同时 gate、up 等中间结果也需要额外写入显存。

本项目把 `gate_proj` 和 `up_proj` 合并成一个更大的线性层，一次性算出 gate 和 up。权重形状从原来的两个 `[intermediate, hidden]` 变成 `[2 * intermediate, hidden]`。这样两次 GEMM 就合并成了一次 GEMM。

```python
# 本项目 — compute/models/qwen3.py Qwen3MLP
self.gate_up_proj = nn.Linear(hidden_size, intermediate_size * 2, bias=False)
self.act_fn = SiluAndMul()          # torch.ops.vllm.silu_and_mul

def forward(self, x):
    x = self.gate_up_proj(x)        # 一次 GEMM，同时得到 gate 和 up
    x = self.act_fn(x)              # 单个 kernel 完成 silu(gate) * up
    return self.down_proj(x)
```

这里的 `silu_and_mul` 会把输入沿最后一维拆成 gate 和 up 两部分，然后在同一个 kernel 里完成 `silu(gate) * up`。相比原来的写法，它不需要单独启动一次逐元素乘法 kernel，也减少了中间张量的显存写入。

## 三、RoPE

朴素参考实现的 RoPE 需要 index_select、chunk、四次 elementwise 和 cat，中间结果反复经过显存。

本项目把 RoPE 换成 FlashInfer 的 `apply_rope_with_cos_sin_cache`，并注册为 custom op 以兼容 torch.compile：

```python
# 本项目 — compute/layers/ops.py
@torch.library.custom_op("vllm::rotary_embedding", mutates_args=())
def rotary_embedding(q, k, positions, cos_sin_cache, head_size):
    n, n_qh = q.shape[:2]
    n_kh = k.shape[1]
    qf = q.reshape(n, n_qh * head_size).contiguous()
    kf = k.reshape(n, n_kh * head_size).contiguous()
    qo, ko = _flashinfer_rope(positions, qf, kf, head_size, cos_sin_cache, is_neox=True)
    return qo.view_as(q), ko.view_as(k)
```

`RotaryEmbedding`（`compute/layers/rotary.py`）预计算 `cos_sin_cache`（`[max_pos, head_size]`，前一半 cos、后一半 sin），forward 时调用 `torch.ops.vllm.rotary_embedding`。

## 四、为什么这几个 kernel 要注册为 custom op

`torch.compile` 对 prefill 做全图编译时，FlashInfer 的 RoPE / SiLU / RMSNorm 内核以及 FlashAttention 无法被 Dynamo trace，必须在 `ops.py` 中注册为 `torch.library.custom_op` 并配 fake 实现：

```python
@silu_and_mul.register_fake
def _silu_and_mul_fake(x):
    return torch.empty((x.shape[0], x.shape[1] // 2), dtype=x.dtype, device=x.device)
```

注册后，编译期把它们当作黑盒（只做形状/dtype 推导），避免 graph break；运行期直接调用底层内核。注意 `fused_add_rmsnorm` 是 inplace 算子，注册时需在 `mutates_args` 中声明被改写的参数，否则编译器会误认为输出是新张量，与 CUDA Graph 捕获的实际写入冲突。

## 五、小结


| 模块         | 朴素参考实现                            | 本项目                                            | 手段      |
| ---------- | ----------------------------- | --------------------------------------------- | ------- |
| RMSNorm    | 5~8 个朴素 kernel                | FlashInfer `fused_add_rmsnorm` 融合核（残差 add 并入） | 换专核     |
| q/k/v 投影   | 3 个 GEMM                      | 1 个 `qkv_proj` GEMM                           | GEMM 合并 |
| gate/up 投影 | 2 个 GEMM + cat                | 1 个 `gate_up_proj` GEMM                       | GEMM 合并 |
| SiLU+Mul   | `F.silu` + `mul` 两核           | FlashInfer `silu_and_mul` 单核                  | 换专核     |
| RoPE       | index_select + chunk + rotate | FlashInfer `apply_rope_with_cos_sin_cache` 单核 | 换专核     |
