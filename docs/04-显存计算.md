# 显存预算与分页利用率

分页实验首先需要区分模型权重、KV 池容量、请求实际使用的 KV 和运行时余量。预先创建的大张量占满显存，不代表其中每个 token 槽位都在有效使用。

## 1. 单位与总预算

```text
1 GB  = 10^9 字节
1 GiB = 2^30 字节
总显存 = 权重 + KV 池 + 激活/临时张量 + 执行缓冲 + CUDA Graph/编译等运行时开销
```

参数量为 P、每参数 b 字节时，权重字节数约为 `P × b`。例如用 0.6×10^9 个参数作估算，FP16 权重约为 1.2 GB，即 1.12 GiB。实际参数量、共享权重和额外缓冲应以加载模型为准。

## 2. 每个 token 的 KV 大小

```text
每 token KV 字节数 = 2 × L × H_kv × d × b
```

| 符号 | 含义 |
|---|---|
| 2 | K、V 两份缓存 |
| L | 模型层数 |
| H_kv | KV 头数，GQA 下使用 num_key_value_heads |
| d | head_dim；不能总是假定等于 hidden_size / num_attention_heads |
| b | 每个缓存元素的字节数，FP16/BF16 为 2 |

对于无共享、实际缓存长度分别为 T_i 的请求，理想有效 KV 字节数为 `每 token KV 字节数 × ΣT_i`。共享前缀的物理存储只计一次；尚未经过前向计算的新生成 token 不应计为已有 KV。

以 `L=28、H_kv=8、d=128、b=2` 这组配置为例，每 token 为 114688 字节，即 112 KiB。4096 个 token 的理想 KV 占用为 448 MiB（0.4375 GiB）。实验应读取实际模型配置核对这些参数。

## 3. 分页后的实际占用

设每块 S 个 token，单块字节数为：

```text
block_bytes = 2 × L × S × H_kv × d × b
```

无共享时，一个长度为 T 的请求需要 `ceil(T/S)` 个块。最后一块可能未满，最多浪费 S−1 个槽位。共享时应统计实际物理块集合，不能把每条请求的逻辑块数直接相加。

课程评测至少分别记录：

- **物理池占用率**：被请求引用的物理块数 / 物理池总块数。
- **已分配块内利用率**：有效物理 token 槽位数 / 已分配槽位数。
- **内部碎片率**：已分配块内未使用槽位数 / 已分配槽位数；分母为零时须约定统计方式。
- **缓存保留量**：无请求引用、但因前缀复用而暂留的块数。
- **共享节省量**：各请求独立保存时所需空间与实际物理空间之差。

连续分配基线还应记录外部碎片，例如总空闲量、最大连续空闲区及因连续空间不足导致的分配失败。内部碎片和外部碎片必须分开报告，分页不意味着最后一块没有浪费。

## 4. 当前代码的预算方法

`KVManager._alloc_pool()` 创建布局为 `[2, layers, blocks, block_size, kv_heads, head_dim]` 的张量池。`auto_num_blocks()` 在模型加载后读取 CUDA 空闲和总显存，以 `gpu_memory_utilization` 扣除已占用内存与传入预留量，再除以单块字节数。

启用 Decode CUDA Graph 时，`ModelExecutor._probe_cg_footprint()` 使用临时 KV 池和图捕获估计附加显存，再调整正式池容量。显式指定 `num_kvcache_blocks` 则跳过自动估算。

该预算属于实现中的估算，仍需要长上下文、不同并发和 Prefill 编译场景的峰值测量。实验同时记录 CUDA allocated/reserved、物理页状态和有效 token 数，才能解释显存去向。

## 5. 页大小与验证边界

当前 GPU 路径要求块大小为 256 的倍数。页越大，页表管理开销通常越小，但短请求最后一页的浪费可能更大。无 GPU 仿真可以扫描不同页大小，GPU 实验只能选择内核支持的参数。

本仓库尚未提供连续分配基线与上述指标的完整采集器。现有 `gpu_memory_utilization` 是分配预算参数，不能把它直接作为实验测得的显存利用率。
