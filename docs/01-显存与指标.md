# 显存预算与分页利用率

KV 池通常会提前分配成一个大张量。即使请求只用了一小部分槽位，CUDA 仍会把整个池计入显存占用。因此，分析显存时需要同时看池的大小和其中的有效数据量。

## 1. 单位与总预算

```text
1 GB  = 10^9 字节
1 GiB = 2^30 字节
总显存 = 权重 + KV 池 + 激活/临时张量 + 执行缓冲 + CUDA Graph/编译等运行时开销
```

参数量为 P、每参数 b 字节时，权重字节数约为 `P × b`。例如用 0.6×10^9 个参数作估算，FP16 权重约为 1.2 GB，即 1.12 GiB。实际参数量、共享权重和额外缓冲应以加载模型为准。

## 2. 每个 token 的 KV 大小

```text
每 token KV 字节数 = 2 × L × H_kv × d × b
```

| 符号 | 含义 |
|---|---|
| 2 | K、V 两份缓存 |
| L | 模型层数 |
| H_kv | KV 头数，GQA 下使用 num_key_value_heads |
| d | head_dim；不能总是假定等于 hidden_size / num_attention_heads |
| b | 每个缓存元素的字节数，FP16/BF16 为 2 |

对于无共享、实际缓存长度分别为 T_i 的请求，理想有效 KV 字节数为 `每 token KV 字节数 × ΣT_i`。共享前缀的物理存储只计一次；尚未经过前向计算的新生成 token 不应计为已有 KV。

以 `L=28、H_kv=8、d=128、b=2` 这组配置为例，每 token 为 114688 字节，即 112 KiB。4096 个 token 的理想 KV 占用为 448 MiB（0.4375 GiB）。其他模型可代入各自配置计算。

## 3. 分页后的实际占用

设每块 S 个 token，单块字节数为：

```text
block_bytes = 2 × L × S × H_kv × d × b
```

无共享时，一个长度为 T 的请求需要 `ceil(T/S)` 个块。最后一块可能未满，最多浪费 S−1 个槽位。共享时应统计实际物理块集合，不能把每条请求的逻辑块数直接相加。

几项指标分别回答不同的问题：

- **物理池占用率**：被请求引用的物理块数 / 物理池总块数。
- **已分配块内利用率**：有效物理 token 槽位数 / 已分配槽位数。
- **内部碎片率**：已分配块内未使用槽位数 / 已分配槽位数；分母为零时须约定统计方式。
- **共享节省量**：各请求独立保存时所需空间与实际物理空间之差。

连续分配还受外部碎片影响：空闲空间总量可能足够，却找不到一段足够长的连续区域。分页消除了这项连续性要求，但最后一页仍可能有空槽位，这部分属于内部碎片。

## 4. KV 池的分配

`KVManager._alloc_pool()` 创建布局为 `[2, layers, blocks, block_size, kv_heads, head_dim]` 的张量池。`auto_num_blocks()` 在模型加载后读取 CUDA 空闲和总显存，以 `gpu_memory_utilization` 扣除已占用内存与传入预留量，再除以单块字节数。

启用 Decode CUDA Graph 时，`ModelExecutor._probe_cg_footprint()` 使用临时 KV 池和图捕获估计附加显存，再调整正式池容量。显式指定 `num_kvcache_blocks` 则跳过自动估算。

预算值用于决定池大小，运行峰值还会受到上下文长度、并发数和执行配置影响。GPU 实验同时记录 CUDA allocated/reserved、物理页状态和有效 token 数。

## 5. 页大小

当前 GPU 路径要求块大小为 256 的倍数。页越大，页表管理开销通常越小，但短请求最后一页的浪费可能更大。无 GPU 仿真可以扫描不同页大小，GPU 实验只能选择内核支持的参数。

## 6. 指标字段

| 字段 | 含义 |
|---|---|
| `resident_pages` / `host_pages_used` | 设备驻留页 / 主机交换页数，两者互斥 |
| `allocated_slots` | 全部唯一活跃页（设备加主机）的容量之和 |
| `useful_slots` | 唯一页中已保留的有效位置，共享前缀只计一次 |
| `logical_tokens` | 各请求逻辑长度之和，共享前缀按请求重复计数 |
| `shared_slots_saved` | `logical_tokens - useful_slots`，有效内容的共享节省量 |
| `pool_occupancy` | 设备驻留页数 / 物理页数 |
| `allocated_utilization` | `useful_slots / allocated_slots` |
| `internal_fragmentation` | `(allocated_slots - useful_slots) / allocated_slots` |
| `swap_in_pages` / `swap_out_pages` | 换入/换出页次；另列从主机复制 COW 的 `host_cow_reads` |

零分母利用率和碎片率均约定为 0。`reserve` 更新逻辑有效长度，GPU 运行器在前向成功后采样指标；失败时应结合请求状态解释。CPU 列表中的一个槽位代表一个 token 的 KV 位置，不代表一个 Python 对象实际占用的字节数。

张量后端报告实际页字节数、传输字节数与同步耗时；满池交换的额外主机 scratch 单独报告。预分配的完整 KV 张量池在请求释放后仍由引擎持有，因此 CUDA allocated 不会随着活跃页数同比下降。

连续基线的内部碎片来自预留槽位与实际长度差，外部碎片为 `1 - 最大连续空闲区 / 总空闲量`（无空闲时约定为 0）。页大小扫描和逐步资源记录见量化报告。`gpu_memory_utilization` 是预算参数，不能直接作为实验测得的利用率。
